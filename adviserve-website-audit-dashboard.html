02 — SEOTechnical SEO is the biggest single lever on this site.

The site is a client-rendered React SPA. Meta tags are injected via react-helmet-async which is great for users with modern crawlers (Google, Bing) but you still need the fundamentals — sitemap, robots, one canonical domain, and a real server-side or SSR-prerendered HTML fallback. Today you're missing almost all of them.

The biggest SEO problem: two hosts, one canonical confusion

index.html uses https://adviserve-website.vercel.app for OG/Twitter tags. SEOHead in every page sets canonical to https://adviserve.in. Google is currently indexing both, splitting authority. First fix: decide the canonical host (almost certainly adviserve.in), 301-redirect the Vercel preview domain to it, update index.html, update SITE_URL in src/lib/constants.ts, and submit a single sitemap.

Sitemap & robots P0

/public has no sitemap.xml or robots.txt. For an SPA behind Vercel that's critical.

Fix:

  • Generate public/robots.txt with Sitemap: https://adviserve.in/sitemap.xml.
  • Add a build-time sitemap generator (vite-plugin-sitemap or a small Node script reading DEFAULT_SERVICES, DEFAULT_HOME_PRODUCTS, blog posts from Supabase).
  • Generate per-type sitemaps: sitemap-services.xml, sitemap-products.xml, sitemap-blog.xml, sitemap-case-studies.xml.

SPA pre-rendering P0

Right now view-source:adviserve.in/services/recruitment shows an empty <div id="root">. Googlebot can render JS, but competing pages that ship HTML beat you on crawl efficiency.

Options (easy → hard):

  • Easy: Add vite-plugin-ssr-prerender or react-snap to pre-render all known static routes at build time. Zero runtime cost.
  • Medium: Migrate to Vite SSR mode for dynamic pages (blog, services) pulling from Supabase.
  • Right-answer: Move to Next.js App Router. This project has already grown into content-heavy territory where SSR pays dividends.

Title & description templates P1

Current homepage title: "Adviserve — End-to-End HR, Recruitment & Business Services" (60 chars — fine). But then SEOHead wraps every page title with | Adviserve, so deep pages become "Business Advisory Services | Recruitment, HR, Legal, IT | Adviserve | Adviserve" — double-branded.

Fix: In SEOHead.tsx, detect if the title already ends with "Adviserve" and skip the suffix. Also keep all titles ≤ 60 chars.

Meta descriptions — write 140–155 char unique descriptions per page. Today, most inherit the hero subtitle which is too long and not keyword-scoped.

Headings & semantic structure P1

Home.tsx uses <h2> correctly per section but no <h1> is rendered server-side (it's inside ModernHeroDemo which may or may not expose h1). Verify every public page has exactly one h1 matching the SEO title concept.

Several sections use div with styled text for what should be h3 (e.g. accordion titles, process step names).

03 — AEO · Answer Engine OptimizationWrite for ChatGPT, Perplexity, Google AIO, Claude, Gemini.

AEO is SEO's next phase — optimizing for AI answer engines. In India, ChatGPT Search and Perplexity are already used for B2B vendor research. Your site has no AEO layer today. The good news: you already have a FAQ system (DEFAULT_FAQS) and FAQ schema. Scale it and restructure your content the way LLMs consume.

Rewrite for extractive Q&A P0

LLMs pull 1–3 sentence answers. Restructure every service and product page into an answer-first format:

Now — narrative"We provide end-to-end human resource services for organisations that need professional HR support without the overhead of a full in-house team…"
AEO — answer-firstWhat does Adviserve HR Services include?
Adviserve HR Services covers policy design, payroll processing, compliance (PF/ESI/POSH/LWF), performance management, HRIS implementation, and fractional CHRO leadership. Pricing starts at ₹X/employee/month for payroll-only engagements and scales to full-function outsourcing.

Canonical FAQ block on every page P0

For every product, service, industry, and city page, add a "People also ask" section with 6–10 Q&As and FAQPage schema. Source the questions from:

  • People Also Ask on Google for your target keyword.
  • Perplexity / ChatGPT — literally ask "What questions do companies ask before buying HRMS in India?" — use top 10.
  • Your own sales/support inbox and call transcripts.

Your existing generateFAQSchema() is already wired up — just add the data.

The "factual block" pattern P1

LLMs love structured facts they can lift. On every product and service page, add a machine-readable facts block:

Adviserve People (HRMS)
- Category: HRMS / HRIS
- Built for: Indian businesses, 10–2,000 employees
- Compliance modules: PF, ESI, PT, LWF, Gratuity, POSH
- Pricing: Free ≤50 employees · ₹X/employee above
- Integrations: Naukri, WhatsApp, Razorpay
- Hosted: India (AWS Mumbai)
- Data: encrypted at rest · DPDP-compliant
- Support: English & Hindi, 9 AM–9 PM IST
- Free trial: yes
- Setup time: < 48 hours
- Exit: full data export, no lock-in

Render it as a styled spec table AND expose it as JSON-LD SoftwareApplication. LLMs extract both.

Citation-friendly content P1

Perplexity and ChatGPT cite sources with author + date + URL. Your blog posts need:

  • Visible author byline with a rel="author" link to a real author page (with credentials, LinkedIn, headshot).
  • Published + last-updated dates.
  • Numbered stats with sources (e.g. "MeitY DPDP Bill, 2023, §17(2)").
  • Schema: Article with author, datePublished, dateModified, publisher.

AI engines prefer quoting dated expert pages over undated marketing pages.

Comparison & alternative pages P0

LLMs dominate comparison queries. Build honest comparison pages:

  • /compare/adviserve-people-vs-keka
  • /compare/adviserve-people-vs-zoho-people
  • /compare/adviserve-people-vs-darwinbox
  • /compare/adviserve-comply-vs-tsaaro
  • /compare/adviserve-hire-vs-naukri-ats

Each page = feature matrix + pricing + honest "use Keka if…" section. Being honest about when not to pick you = massive trust signal.

"Definition" pages P1

ChatGPT answers queries like "what is DPDP act" by pulling a dictionary-style definition. Claim it:

  • /glossary/dpdp-act
  • /glossary/posh-compliance
  • /glossary/employer-of-record
  • /glossary/hrms-vs-hris-vs-hcm
  • /glossary/rpo (Recruitment Process Outsourcing)

Use DefinedTerm schema. 400–600 words each. Link to your service pages.

LLM-ready site summary page P1

Create /llms.txt (emerging standard) and /about/company-facts — a single page where an LLM can find:

  • Legal name, founded, HQ, offices.
  • Founders, current leadership, total team size.
  • All services, all products, pricing summaries.
  • Client count, industries served, geographies.
  • Press mentions, certifications, awards.

This is what models pull into their knowledge graph. Make the truth easy to find.

LLMs represent knowledge as entity graphs. Strengthen yours by consistently naming entities:

04 — GEO · Generative/Geographic Engine OptimizationTwo meanings — and you're weak on both.

"GEO" means two things in 2026: (1) Generative Engine Optimization (overlaps with AEO — mostly covered above) and (2) Geographic Optimization — ranking for "in <city>" searches. Your audience is pan-India B2B. You currently target zero cities. This is the largest under-exploited SEO surface on the site.

City landing pages P0

Launch 6 priority cities first:

  • /locations/bengaluru — tech, startups, RPO
  • /locations/mumbai — BFSI, media, manufacturing
  • /locations/delhi-ncr (Gurugram, Noida, Delhi) — enterprise & consulting
  • /locations/pune — IT & auto
  • /locations/hyderabad — tech & pharma
  • /locations/chennai — manufacturing, GCCs

Each page = unique content (local market context, regulations specific to state, case studies from that city, office address if any, local team). Don't copy-paste — Google will flag it as doorway pages.

Follow-on tier: Ahmedabad, Jaipur, Kolkata, Coimbatore, Kochi, Indore, Chandigarh.

LocalBusiness schema per city P0

You already have generateLocalBusinessSchema() — wire it up. Each city page needs:

{
  "@type": "ProfessionalService",
  "name": "Adviserve — Bengaluru",
  "address": { "addressLocality": "Bengaluru", "addressRegion": "KA", "addressCountry": "IN" },
  "areaServed": ["Bengaluru Urban", "Whitefield", "Electronic City", "Koramangala"],
  "geo": { "latitude": "...", "longitude": "..." }
}

If you have physical offices in those cities, add Google Business Profile listings and link them.

Hreflang is NOT needed — skip

India is a single-country audience. Don't add hreflang or multilingual duplication yet. But DO add lang="en-IN" to <html> (currently en) and set a content-language meta of en-IN for accurate local ranking.

State-wise labour law hub P1

Huge India-specific SEO opportunity your competitors ignore:

  • /guides/labour-law/delhi

Minimum wage tables, S&E registration, PF filing deadlines per state. Update quarterly. This drives massive high-intent traffic from HR / Finance teams. Gate the detailed checklist → lead magnet.

Currency, units, and local idiom P2

Content already uses ₹ and Indian phrasing — good. But:

  • Testimonial companies: use "Bengaluru" (not "Bangalore"), "Gurugram" (not "Gurgaon"). Consistency signals local fluency.
  • Dates: use DD Month YYYY or ISO; not US MM/DD/YYYY.

Generative Engine snippets P1

For the generative side of GEO (already covered in AEO):

  • Wikipedia-style "about" paragraphs on every entity (service, product, location).
  • Clear "what it is / who it's for / what it costs / what next" rhythm.

05 — UI / UX DesignPremium aesthetic, but the system is drifting.

The design direction is ambitious and distinctive — font-mono section numbers (// 00.01°), editorial typography, generous whitespace, orange + teal brand pair, light/dark theme, magnetic CTAs, GSAP-driven reveals. It reads like a high-end agency site. Problems are not taste — they're consistency, hierarchy, and over-engineering.

Design tokens drift P1

Multiple color sources:

  • tailwind.config.js tokens: brand-orange #d95d39, brand-teal #6dd4c4, brand-lightOrange, brand-darkOrange, brand-lightTeal.
  • Inline hex: #1a1a2e, #0d1b2a, #111111, #161616, #F9F9F6, #faf9f6, #1f1f1f — scattered through components.
  • Opacity modifiers everywhere: white/40, black/5, text-white/60 — inconsistent from section to section.

Fix: codify tokens into CSS variables or Tailwind theme extensions: --surface, --surface-elev, --text-primary, --text-secondary, --text-muted, --border, --border-soft. Nuke every raw hex. One source of truth.

Typography hierarchy P1

You have 5 fonts loaded: Bebas Neue, DM Sans, DM Serif Display, Inter, Space Mono. That's a lot.

  • Pick a role for each — e.g. DM Serif for editorial h1/h2, Inter for UI + body, Space Mono for all // 00.0x° labels. Remove Bebas (overlaps with DM Serif) unless it's serving a distinct role.
  • Define 6–7 type styles: display/xl, display/lg, h1, h2, h3, body/lg, body, caption, mono/sm. Document them on a /style-guide dev-only page.
  • Many headings use clamp(36px, 5vw, 64px), others use clamp(32px, 7vw, 72px), others clamp(30px, 4vw, 52px) — consolidate.

Component sprawl P1

In src/components/ui/ you have: tabs.tsx, vertical-tabs.tsx, why-adviserve-tabs.tsx, cards-stack.tsx, expandable-card.tsx, clip-path-links.tsx, hero-demo.tsx, modern-hero-demo.tsx, modern-animated-hero-section.tsx, interactive-hero-backgrounds.tsx, interactive-image-accordion.tsx, plus demo.tsx, material-design-3-switch.tsx, svg-follower.tsx, pricing-card.tsx…

That's 3 tab variants, 3 hero variants, and multiple unused or demo files in production. This is how design systems rot. Do a week of pruning.

Hero readability P1

Current hero has six layered elements: full-bleed particles + floating orbs + scroll cue + animated text cycle + CTA + badge. On a 1440px screen it reads well; on a 13" laptop, the text competes with the particles. Check contrast AA on the hero subtitle against the particles background — it looks borderline.

Fix: add a subtle linear-gradient overlay (rgba(0,0,0,.3) → transparent) behind the hero text. Dim the particles opacity from 0.8 to 0.4 when text is present.

Motion budget P0

The homepage has at minimum: GSAP timeline on advantage cards, connector draw-in, proof strip counter, benefits stagger, industry wave + infinite float loop, hero text cycle, 2 opposing marquees, ISO cert 3D flip + rotating text bands + infinite glow pulse, magnetic CTA on footer, and Lenis smooth scroll on top. That's a lot — browser reports show this kind of site runs at < 45fps on mid-tier Android.

  • Motion budget: at most 2 concurrent animations per viewport. Chain them; don't parallelize.

+ Accessibility (WCAG 2.1 AA)Good starts, systemic gaps.

The codebase shows real a11y intent — focus-visible:ring utilities, skip-to-content link, aria-labels on search, prefers-reduced-motion guards on most animations, sr-only labels. It's not accidental. But there are systemic gaps that will fail an automated scan and fail real users.

Color contrast P1

  • text-white/40 and text-white/60 on #111111 backgrounds is common — white/40 is ≈ 3.5:1 which fails AA for body text (4.5:1).
  • text-text-dim-like values on light backgrounds similarly borderline.
  • Brand orange #d95d39 on white = ~4.3:1 — fails AA for body, passes AA Large.

Fix: audit all 40%/50% text-on-dark uses. Bump to 60%+ minimum. Avoid orange-on-white for body text; reserve it for large headings or use as accent-only.

Motion & reduced-motion P1

You guard most animations with prefers-reduced-motion (good). Missing guards:

  • Marquee animations run regardless (motion-safe:animate-marquee is correct — verify every marquee variant uses it).
  • ISO cert rotating band and glow pulse: the code has a check but still runs infinite animations on focus — pause when reduced-motion is on.
  • Intersection-observer driven "pause when offscreen" isn't implemented. Infinite animations keep running when the section is scrolled away, chewing CPU on slow devices.

Keyboard navigation P1

  • Tabs component: verify arrow-key navigation (WAI-ARIA tabs pattern). Today it appears to be button-based only — tab cycles through all 5 tabs instead of arrow-left/right switching.
  • Accordion (InteractiveImageAccordion): add aria-expanded on the triggers and proper ids for aria-controls.
  • Custom cursor: must be disabled when keyboard is the input modality (and for touch). Currently the CustomCursor always renders.
  • Modal (SearchModal): confirm focus trap, escape-to-close, focus returned to trigger on close.
  • Cookie consent: must be keyboard-operable and announced to screen readers on mount.

Focus rings P2

Focus styles are inconsistent — some components have focus-visible:ring-2 focus-visible:ring-brand-teal, others none. Global tailwind plugin or base layer rule:

@layer base {
  *:focus-visible {
    outline: 2px solid var(--accent-2);
    outline-offset: 2px;
  }
}

Alt text audit P0

Most images have alt text. Where they don't (or where it's poor):

  • Unsplash images on homepage tabs: alt="Problem", alt="Shift", alt="Result" — not descriptive.
  • Logo: verify alt="Adviserve" is set (not alt="").
  • Icon-only buttons (arrow, close) need aria-label if there's no visible text.
  • Decorative images: explicit alt="" + aria-hidden="true".

Form accessibility P1

  • Contact form: verify every input has a visible or sr-only label (you use sr-only on the search input — good).
  • Error messages: must be announced via aria-live="polite".
  • Success states: same pattern.
  • Required fields: visible asterisk + aria-required="true".
  • Autocomplete attributes: autocomplete="email", "name", "tel", "organization".

Heading order P1

Likely skips levels (h1 → h3 common on card-heavy pages). Run axe / Lighthouse per page and fix. Use h2 for sections, h3 for card titles. Never skip a level.

Screen reader walkthrough P2

Do a 30-min pass with NVDA (Windows) or VoiceOver (Mac). Check: landmark navigation (header/main/footer), list semantics (tiles should be in ul>li), button vs link (search clear = button, "Learn more" = link).

Language attribute P2

<html lang="en"> — fine, but en-IN is more accurate and helps local SEO + screen reader pronunciation for Indian names and places.

What's working Keep

  • prefers-reduced-motion guards on most GSAP timelines.
  • aria-labels on icon-only inputs.
  • noscript fallback in index.html.
