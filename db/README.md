# Database & Migration Sources — Map of Truth

This repository has historical SQL in **five** locations. New work must use
only the canonical sources listed below. The legacy files are kept for
reference but are not the source of truth and should be removed once the
team confirms no environment still bootstraps from them.

## Canonical (source of truth)

| Path | Purpose |
| --- | --- |
| `supabase/migrations/*.sql` | **All forward schema changes.** Each migration file is timestamped and applied via the Supabase CLI. Add new tables / columns / policies here. |
| `scripts/seed-data.ts` + `scripts/run-seed.ts` | **Idempotent CMS seed.** Runs at build time. Inserts default content into `website_pages`, `website_content`, etc. without overwriting admin edits. |
| `scripts/004_cms_migration.sql` | **One-off CMS bootstrap.** Creates `products`, `case_studies`, `job_positions`, `job_applications`, `dpdp_assessments`. Should be folded into `supabase/migrations/` and deleted. |

## Legacy (kept for archaeology — do not modify)

| Path | Status |
| --- | --- |
| `db/migration.sql`, `db/migration-v2.sql` | Predates the Supabase CLI flow. Defines the same tables as `supabase/migrations/` with slightly different policies. **Delete after team sign-off.** |
| `supabase/all_migrations_combined.sql` | Snapshot bundle, regenerated by hand. Stale. |
| `supabase/fresh_setup.sql` | Bootstrap for a brand-new database without migration history. Useful only for a clean dev install. |
| `supabase/schema_fixes.sql`, `seo_migration.sql`, `theme_setting.sql`, `unsubscribe_policy.sql`, `seed_blog_and_settings.sql` | One-off scripts applied during the original rollout. Should be folded into timestamped migrations. |

## How to add a new schema change

```bash
supabase migration new my_change
# edit the generated file under supabase/migrations/
supabase db push        # apply to remote
```

Do **not** edit `db/migration*.sql`, `supabase/fresh_setup.sql`, or
`supabase/all_migrations_combined.sql`. They are read-only.
